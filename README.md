# scoringutils-py

[![tests](https://github.com/gregnewkirk/scoringutils-py/actions/workflows/tests.yml/badge.svg)](https://github.com/gregnewkirk/scoringutils-py/actions/workflows/tests.yml)
[![release](https://img.shields.io/github/v/release/gregnewkirk/scoringutils-py)](https://github.com/gregnewkirk/scoringutils-py/releases)

What changed in each version: [CHANGELOG.md](CHANGELOG.md). How to contribute and release: [CONTRIBUTING.md](CONTRIBUTING.md).

An unofficial Python port of the R package
[scoringutils](https://github.com/epiforecasts/scoringutils) for evaluating
probabilistic forecasts. Version 0.2.0 covers quantile, sample, point and
binary forecasts and matches scoringutils 2.3.0 (CRAN, 2026-09-27) to within 1e-10, as
checked against output generated by R itself.

> **Credit.** scoringutils is written by Nikos Bosse, Sam Abbott, Hugo
> Gruson, Sebastian Funk and contributors at
> [epiforecasts](https://epiforecasts.io/), and released under the MIT
> licence. Its design, metric definitions, defaults, example data and test
> cases are all theirs. This repository translates that work into Python.
> It is not affiliated with or endorsed by the scoringutils authors. If
> you use it, please cite the original package (see [Citation](#citation)).

## Why

scoringutils is a widely used R package for scoring epidemiological
forecasts (weighted interval score, CRPS, bias, coverage, relative skill). Python users have the
scoring maths in [scoringrules](https://github.com/frazane/scoringrules),
but nothing for the data-frame workflow around it: checking that forecasts
are well formed, detecting the forecast unit, scoring a whole table,
summarising by model, and comparing models pairwise. This package fills
that gap with the same function names and arguments as R, so existing
scoringutils code translates almost line by line.

## Install

Not on PyPI yet. From a clone of this repository:

```bash
uv sync
```

or with pip:

```bash
pip install .
```

Requires Python 3.10 or later, numpy, pandas 2, scipy and scoringrules
(0.9 to 0.11).

## Worked example

This uses the example data that ships with scoringutils: quantile forecasts
of COVID-19 cases and deaths from the European Forecast Hub.

```python
import scoringutils_py as su

forecast = su.as_forecast_quantile(su.example_quantile())
forecast.forecast_unit
# ['location', 'target_end_date', 'target_type', 'location_name',
#  'forecast_date', 'model', 'horizon']
```

`as_forecast_quantile()` checks the data (required columns, duplicate
forecasts, constant observations within a forecast, equal numbers of
quantiles) and works out the *forecast unit*: the columns that together
identify one forecast.

Score every forecast, then summarise:

```python
scores = su.score(forecast)
scores.metrics
# ['wis', 'overprediction', 'underprediction', 'dispersion', 'bias',
#  'interval_coverage_50', 'interval_coverage_90', 'ae_median']

su.summarise_scores(scores, by=["model", "target_type"])
```

```
                   model target_type        wis  overprediction  underprediction  dispersion    bias  interval_coverage_50  interval_coverage_90
0  EuroCOVIDhub-ensemble       Cases  17943.824       10043.122         4237.177    3663.525  -0.056                 0.391                 0.805
1  EuroCOVIDhub-baseline       Cases  28483.575       14096.101        10284.973    4102.501   0.098                 0.328                 0.820
2   epiforecasts-EpiNow2       Cases  20831.557       11906.823         3260.356    5664.378  -0.079                 0.469                 0.789
3  EuroCOVIDhub-ensemble      Deaths     41.422           7.138            4.103      30.181   0.073                 0.875                 1.000
...
```

Relative skill from pairwise comparisons, scaled so the baseline model
scores 1 (lower is better):

```python
rel = su.add_relative_skill(scores, by="target_type", baseline="EuroCOVIDhub-baseline")
su.summarise_scores(rel, by=["model", "target_type"])[
    ["model", "target_type", "wis", "wis_relative_skill", "wis_scaled_relative_skill"]
]
```

```
                   model target_type        wis  wis_relative_skill  wis_scaled_relative_skill
0  EuroCOVIDhub-baseline       Cases  28483.575               1.295                      1.000
1  EuroCOVIDhub-baseline      Deaths    159.404               2.296                      1.000
2  EuroCOVIDhub-ensemble       Cases  17943.824               0.816                      0.630
3  EuroCOVIDhub-ensemble      Deaths     41.422               0.597                      0.260
4        UMass-MechBayes      Deaths     52.652               0.748                      0.326
5   epiforecasts-EpiNow2       Cases  20831.557               0.947                      0.731
6   epiforecasts-EpiNow2      Deaths     66.643               0.977                      0.425
```

`su.get_pairwise_comparisons(scores)` gives the full table of model pairs
with score ratios and Wilcoxon p-values, and `su.get_coverage(forecast)`
gives interval and quantile coverage per quantile level.

Sample forecasts work the same way and use CRPS-based metrics:

```python
scores = su.score(su.example_sample_continuous())
su.summarise_scores(scores, by="model")[["model", "crps", "log_score", "dss", "bias", "mad"]]
```

```
                   model       crps  log_score     dss   bias        mad
0  EuroCOVIDhub-ensemble   9876.959     10.748  16.405  0.010   8763.618
1  EuroCOVIDhub-baseline  15309.686        inf     NaN  0.178   9680.379
2   epiforecasts-EpiNow2  11901.434        inf  26.101 -0.025  12999.540
3        UMass-MechBayes     60.190      5.942  10.086 -0.027    123.621
```

The `inf` and `NaN` values are also what R gives: a few forecasts in the
example data have all 40 samples equal to 0, so the kernel density
estimate behind the log score, and the variance behind the
Dawid-Sebastiani score, degenerate.

To convert samples to quantiles: `su.as_forecast_quantile(sample_forecast,
probs=[0.05, 0.25, 0.5, 0.75, 0.95])`. All nine R `quantile()` types are
supported through `type=`.

### Point and binary forecasts

A point forecast is a single number per target, scored with the absolute
error (`ae_point`), squared error (`se_point`) and absolute percentage
error (`ape`). A quantile forecast becomes a point forecast by keeping its
median:

```python
point = su.as_forecast_point(su.as_forecast_quantile(su.example_quantile()))
su.summarise_scores(su.score(point), by=["model", "target_type"])
```

```
                   model target_type   ae_point   se_point    ape
0  EuroCOVIDhub-ensemble       Cases  24101.070  3.890e+09  0.436
1  EuroCOVIDhub-baseline       Cases  38473.602  5.767e+09  0.855
2   epiforecasts-EpiNow2       Cases  27923.812  5.173e+09  0.431
3  EuroCOVIDhub-ensemble      Deaths     53.133  6.579e+03  0.163
...
```

A binary forecast is a probability that something happens, scored with the
Brier score and the log score. R stores the outcome as a factor with two
levels; the Python equivalent is a pandas `Categorical` with two
categories, and `predicted` is the probability of the second one:

```python
# your own data: outcomes 0 / 1 in `observed`, probabilities of a 1 in `predicted`
df["observed"] = pd.Categorical(df["observed"], categories=[0, 1])
forecast = su.as_forecast_binary(df)

scores = su.score(su.as_forecast_binary(su.example_binary()))
su.summarise_scores(scores, by="model")
```

```
                   model  brier_score  log_score
0  EuroCOVIDhub-ensemble        0.243      0.680
1  EuroCOVIDhub-baseline        0.192        inf
2   epiforecasts-EpiNow2        0.252      0.697
3        UMass-MechBayes        0.246      0.685
```

The baseline's `inf` log score is also what R gives: it put probability 0
on an outcome that happened.

### Custom metrics

Metrics are a dict of `name -> function`, like R's named list. Use
`functools.partial` where R uses `purrr::partial`:

```python
from functools import partial

metrics = su.get_metrics(forecast, select=["wis", "bias"])
metrics["wis"] = partial(su.wis, count_median_twice=True)
metrics["interval_coverage_80"] = partial(su.interval_coverage, interval_range=80)
su.score(forecast, metrics=metrics)
```

A quantile metric is called as `f(observed, predicted, quantile_level)`
and a sample metric as `f(observed, predicted)`. `predicted` is a matrix
with one row per forecast. Point and binary metrics are called as
`f(observed, predicted)` with one value per forecast in each. As in R, a metric that raises an error is
skipped with a warning and the others still run.

## Translating from R

| R | Python |
|---|---|
| `as_forecast_quantile(df)` | `su.as_forecast_quantile(df)` |
| `score(fc)` | `su.score(fc)` |
| `summarise_scores(scores, by = c("model", "target_type"))` | `su.summarise_scores(scores, by=["model", "target_type"])` |
| `get_metrics(fc, exclude = "ae_median")` | `su.get_metrics(fc, exclude="ae_median")` |
| `purrr::partial(wis, na.rm = TRUE)` | `functools.partial(su.wis, na_rm=True)` |
| `NULL` | `None` |
| `attr(scores, "metrics")` | `scores.metrics` |
| `example_quantile` | `su.example_quantile()` |
| `factor(x, levels = c(0, 1))` | `pd.Categorical(x, categories=[0, 1])` |

## How parity is tested

R is not needed to run the tests. Expected values are generated once in R
and committed:

1. [`r/generate_fixtures.R`](r/generate_fixtures.R) runs against pinned R
   scoringutils 2.3.0 and scoringRules 1.1.3 (R 4.6.1, recorded in
   [`tests/fixtures/versions.json`](tests/fixtures/versions.json)) and
   refuses to run with other versions. It writes CSV and JSON fixtures with
   17 significant digits, so every double survives the trip exactly.
2. [`tests/test_parity_dataframes.py`](tests/test_parity_dataframes.py)
   compares 47 data-frame results (`score()` on all five example datasets
   and on edge cases, `summarise_scores()`, `get_pairwise_comparisons()`,
   `add_relative_skill()`, `get_coverage()`, `get_duplicate_forecasts()`,
   sample to quantile conversion for all nine quantile types, quantile to
   point conversion) column by column, including row order.
3. [`tests/test_parity_metrics.py`](tests/test_parity_metrics.py) runs 125
   vector-level cases: every metric on hand-built and random inputs (the
   random draws were made in R and stored), with quantile levels 0 and 1,
   a missing median, NA values, ties, integer samples, reversed factor
   levels, probabilities of exactly 0 and 1, and the Wilcoxon test with
   ties and zeros.
4. The remaining tests port the upstream testthat cases for forecast
   objects (quantile, sample, point, binary), metrics, scoring,
   summarising, pairwise comparisons and coverage.

Tolerance is `rtol=1e-10`. In practice most values agree to within 1e-15
relative. The one exception is the CRPS over- and underprediction
components for samples, each computed as a difference of two CRPS values:
when the true value is 0, R and Python each return rounding noise (about
1e-15 times the CRPS), so those columns are compared on the scale of the
CRPS. The suite runs on Python 3.10 (scoringrules 0.9) and 3.12
(scoringrules 0.11).

Two things I have not been able to pin down yet. R sorts groups of
quantile levels as strings in the session's locale, so on a machine with
an unusual collation the row order of `score()` output could differ from
what is tested here (the values would not). And the parity fixtures cover
the example data plus constructed edge cases; real hub submissions with
missing quantiles in odd places may still find a case nobody has tried.
Bug reports with a small reproducible example are welcome.

To regenerate the fixtures (needs R with the pinned packages):

```bash
Rscript r/generate_fixtures.R
```

## Differences from R

- A forecast is a pandas DataFrame subclass, and any pandas operation that
  returns a new frame (filtering, merging, `copy()`) gives back a plain
  DataFrame. Call `as_forecast_quantile()` again before scoring an edited
  forecast. R re-validates after every subset and warns instead. `Scores`
  objects do keep their metric list through filtering and copying, as in R.
- R messages become warnings of category `su.ScoringutilsMessage`, which
  `warnings.simplefilter("ignore", su.ScoringutilsMessage)` silences. R
  warnings become `UserWarning` and R errors become `ValueError` or
  `TypeError`. The wording follows R closely but is not identical.
- R stores missing coverage values as logical `NA`. Here, score columns
  that mix `True`/`False` with missing values use pandas' nullable
  `boolean` dtype, and `interval_coverage()` returns floats with `NaN` when
  an interval bound is missing.
- Permutation tests (`test_type="permutation"`) draw numpy random numbers,
  so their p-values differ from R's even with a seed. Pass `rng=` (a seed
  or a `numpy.random.Generator`) to make them reproducible.
- `summarise_scores(fun=...)` passes each group to `fun` as a numpy array.
  `np.std` defaults to `ddof=0` while R's `sd` uses n - 1, so pass
  `fun=np.std, ddof=1` to match R. Boolean score columns are turned into
  0 / 1 first, which means `fun=np.median` works on coverage columns (in R,
  `fun = median` can error on them).
- `na.rm` is spelled `na_rm`. `probs` and `type` are only accepted by
  `as_forecast_quantile()` when converting a sample forecast; R silently
  ignores them otherwise.
- Calling `get_duplicate_forecasts()` on a plain DataFrame without `type=`
  raises a `FutureWarning`, matching R's deprecation in 2.3.0.
- Binary forecasts need `observed` as a pandas `Categorical` with exactly
  two categories, the closest thing to an R factor. Integers, booleans and
  strings are refused with a hint, as R refuses non-factors. The second
  category plays the role of R's highest factor level.
- R's default point metrics are unnamed functions inside
  `get_metrics()`. Here they are also importable as `su.ae_point()`,
  `su.se_point()` and `su.ape()`. As in R, they do not check their input,
  and `ape()` returns `inf` without a warning when the observed value is 0.
- `as_forecast_point()` on a quantile forecast does not accept
  `forecast_unit`, `observed` or `predicted`; R silently ignores them.

## Notes on scoringrules

Where scoringutils calls the R package scoringRules, this port calls the
Python package scoringrules with the settings that reproduce R exactly.
Each mapping is covered by a parity test:

| scoringutils (R) | scoringrules (Python) |
|---|---|
| `crps_sample()` (`method = "edf"`) | `crps_ensemble(estimator="qd")`. The other estimators (`"pwm"`, `"fair"`) give different numbers. |
| `logs_sample()` | `logs_ensemble(bw=bw.nrd(x))`, plus R's behaviour when all samples are equal (bandwidth 0), where scoringrules returns `NaN` and R returns `Inf`. |
| `dss_sample()` | `dssuv_ensemble(bias=True)`. The default `bias=False` differs. |
| `quantile_score()` | Not used: scoringutils' quantile score is twice the pinball loss returned by `scoringrules.quantile_score`. |
| `wis()` | Implemented directly, following the R code. scoringrules 0.9 to 0.11's numpy backend for `weighted_interval_score` adds `w_median * median` where it should add `w_median * abs(obs - median)` (the numba backend is correct), and the R function also returns its components and handles quantile levels 0 and 1. |

scoringrules 0.11 requires Python 3.12. On Python 3.10 and 3.11 the
package installs scoringrules 0.9, which has the same API and gives the
same results for everything used here.
